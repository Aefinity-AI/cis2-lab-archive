## Pins and ambiguities for the orchestrator (amend-bar before start only; none loosens the mark)
1. Rust build form. Bar: "Rust is a static musl cross-build made on penguin" for box4/box5 and "built as static libraries with one C ABI". Built here: no_std objects in static libraries, no musl involved, identical bytes on every host, linked by the host gcc. Pin the rustc version, flags, the ten library sha256 values above and say so.
2. K2 cannot share a process with the C arms, so "arm order rotated every rep" holds inside the harness (ours, K1, K3, K4) and K2 is two bracketing passes of 10 reps each (before and after). Pin this, or accept K2 as 20 values from two passes.
3. Load rule "host load 0.3 or more before or after": a one-minute load average includes our own busy core (about 1.0) during timing. Implemented: opening gate = 1-min load below 0.3 and no other leg unit; every repetition records the load average and the other-runnable count; any other leg unit at the closing check = FAIL. The in-run load average is recorded, not used as a gate. Pin that reading.
4. Input sets: the bar says 5 fixed sets; the gate (memcmp) runs on all 5 sets on every host and tier, timing uses set 0. Pin or ask for rotation.
5. "Three discards make that host INVALID": read as the third discard in one job fails (2 tolerated), one budget shared across K2 pass A, the harness (all tiers) and K2 pass B (run.sh hands each process the remainder). A redo job (R5_REPS/R5_SHAPE) starts a fresh budget of 2, so the host total over a first job plus redo jobs can exceed 2; pin that reading. A per-repetition reading is looser. Clock-drop reference = highest pinned-core MHz seen so far in the run (cpuinfo "cpu MHz"); the threshold is 15 percent.
6. NOT RUN: the bar does not say what happens to a library arm that cannot be prepared (it only allows box4/box5 OpenBLAS "if a static build runs"). Jobs print `NOTRUN arm=... reason=...` and carry on; the result writer needs a sentence for a library with no label.
7. Part B tier pairing: libraries appear in both tier passes on box1 (T0 pass and T1 pass), each compared with the kernels timed in the same pass, so T0 against libraries (no label) and T1 against libraries (labelled) use concurrent reps.
8. Thread check: harness checks /proc/self/status Threads after the opening call of every library arm (1 required); k2_torch.py prints Threads and torch thread counts (1 on penguin). A torch process on a box could show helper threads; the count is printed, judged by the result writer.
9. Penguin has no AVX2 constraint but the boxes 2 to 5 do: T1 is built everywhere (compile only) and run on box1 only; the harness never calls T1 arms elsewhere.
