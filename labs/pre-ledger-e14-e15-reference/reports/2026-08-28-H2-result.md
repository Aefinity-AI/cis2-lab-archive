# H2 result — transcendental accuracy characterization (cis2-fp, private)

Branch: `cm/h2-transcendental-rigor` (pushed). Files:
`docs/H2_TRANSCENDENTAL_RIGOR.md` (new), `docs/CIS2_SPEC_v0.2.md` §6.7 (new addendum).
No coefficients changed; `table_digest()` unaffected. `cargo check` clean.

Method: ported §6 pinned functions line-for-line into Python (numpy.float32,
same single-rounding semantics), oracle = mpmath 60-digit + candidate-neighbor
search for the correctly-rounded fp32 value. Domain derived analytically from
the ops (softmax post-max-sub ≤0, SiLU gate args, RoPE inv_freq
exponents/angles, pos≤19 per §13's 20-position decode), then measured on the
exact grid the two pinned test vectors (SmolLM2-135M θ=1e5, Qwen2.5-0.5B
θ=1e6) actually use.

Results (max ULP vs correctly-rounded fp32 / max relative error):
- `rsqrt_cr`: 0 ULP (correctly rounded by construction).
- `exp_pinned`: ≤1 ULP, 1.19e-7 rel, over x∈[-40,40] and the exact RoPE grid.
- `ln_pinned`: 0 ULP at both pinned rope_theta values (1e5, 1e6); ≤1 ULP over
  a padded scan.
- `sin_pinned`/`cos_pinned`: up to **1104 ULP / 1.00e-4 rel** (SmolLM2, exact
  grid, pos≤19) — **FINDING**, exceeds the 4-ULP concern threshold. Root
  cause: `reduce_2pi`'s two-constant range reduction done entirely in f32
  (no-FMA/no-f64 constraint) suffers catastrophic cancellation growing
  linearly with position index — not polynomial inadequacy. Determinism is
  unaffected (still exactly bit-reproducible pure fp32 arithmetic); this is
  an accuracy-only concern. Grows much worse (≥0.58 rel) if decode length
  were ever extended toward max_position_embeddings=8192 — informative only,
  out of scope for §13's 16-token pinned test vector.

Suggested NEEDS.md/BLOCKERS.md entry: none blocking — H2 gap is closed with
evidence (not a fix). Flag for future work: if CIS-2 ever extends pinned
decode length beyond ~20 positions, re-run
`docs/H2_TRANSCENDENTAL_RIGOR.md`'s characterization before trusting
sin/cos accuracy at the new length.
