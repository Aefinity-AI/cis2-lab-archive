## Claim (conservative wording)
A normative specification (docs/CIS2_SPEC_v0.1.md, branch cm/e15f-spec-v0.1) for fp32 transformer decode such that
two implementations written independently from it produce bit-identical full-logit digests on x86_64 and aarch64,
across compilers/opt-levels, for two model families, matching PyTorch within oracle tolerance.

## Mechanism (named)
fp32 only; FTZ/DAZ pinned (MXCSR / FPCR.FZ); RNE; no FMA/contraction (verified by objdump); scalar left-to-right
reductions; exp/sin/cos as pinned Cephes-style polynomials (hex-pinned coefficients, Horner) — no platform libm;
sqrt/div IEEE correctly rounded; RoPE inv_freq built by pinned ops; digest = SHA-256 chain over full logit bit
patterns per step + header.

## Why this is the "hard case"
Integer (CIS-1) identity across ISAs is expected once accumulators are bounded. Floating-point identity across
x86/ARM/compilers is what every prior line (batch-invariant kernels, LLM-42, MarginGate, Cankaya GPU emulation)
treats as unattainable or approximates statistically. E15g shows it is a spec property.

## Known limitations (state them, do not hide them)
- fp32 scalar reference: not a fast kernel; 135M/0.5B models; greedy only; CPU only.
- Reference weaknesses (E15h queued): LN_THETA literal (config-generality claim overstated); table digests not
  folded into the receipt; artifact hashes hashed as hex ASCII. Spec v0.2 + new preregistered digest will follow.
- Not yet: phone (consumer aarch64) leg for CIS-2; transcendental route pinned by fiat (route b), not correctly rounded.

**Scope correction (honest):**
- PROVEN: (i) cross-ISA (x86_64/aarch64) + cross-compiler (20 configs) + cross-model-family full-logit bit-identity; (ii) an independent *Rust* clean-room (E15g/verify2) reproduces the full-logit digest from the spec alone; (iii) an independent *C* clean-room reproduces the exact TOKEN stream + argmax digest + table digests from the spec alone.
- NOT YET PROVEN: full-logit-digest identity ACROSS LANGUAGES. The C impl diverges in the per-step logit bytes without changing any argmax → spec v0.2 forces token determinism cross-language but not full-logit determinism cross-language. Residual gap (candidate causes: a reduction/accumulation the spec doesn't pin tightly enough for a non-Rust compiler, or the logit-serialization byte order — E15k will localize via intermediate hashes).
- The "definitive determinism" claim stands on (i)+(ii). The cross-language leg currently strengthens the TOKEN claim and is a stated limitation for the full-logit claim, not a refutation.

## Update 13:55 CT — E15k RESOLVED: cross-language identity ACHIEVED (rescope reversed)
The E15j C-vs-Rust full-logit mismatch was a **spec defect, not numerics**: spec §12.1 documented the witness-chain
SHA-256 update order (table, inv_freq, weights, tokenizer, config) differently from what the reference actually did
(weights, tokenizer, config, table, inv_freq). All 5 inputs were already bit-identical; only the documented order was
wrong, and the C clean-room faithfully implemented the wrong prose. Fixed spec §12.1 + verify3; **E15j now 4/4 bit-exact**
(CI 33200155942): the C implementation reproduces a0c563ef… on x86_64+aarch64 under gcc AND clang.

**Definitive claim, now airtight:** an fp32 transformer forward pass specified so that THREE independent implementations
— the Rust reference, an independent Rust clean-room (verify2), and an independent C clean-room (verify3) — produce
bit-identical full-logit witness digests across x86_64 and aarch64, across gcc/clang and 20 compiler configs, over two
model families and 128-token horizons, matching a PyTorch oracle. The clean-room process itself surfaced and fixed a
real spec defect — evidence the spec (v0.2, §12.1 corrected) is now sufficient for a from-text-only implementer in a
different language. The earlier "cross-language not yet proven" caveat is CLOSED. Merged to cis2-fp main.
