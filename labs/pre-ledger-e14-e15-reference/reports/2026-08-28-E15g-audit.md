## (1) INDEPENDENCE — PASS (with caveats)

- Git history: verify2/ was added in a single commit (7eb7ac5), all 8 files
  status "added" (A), no rename/copy detected by git:
  `git log --diff-filter=A --oneline -- verify2/` → only that one commit.
  `git show --stat 7eb7ac5` shows verify2/src/{fpenv,main,math}.rs created
  fresh, no history linking them to src/ or verify/ blobs.
- Verbatim line overlap (normalized whitespace, blank/comment lines excluded,
  restricted to lines >=20 chars to exclude trivial boilerplate like `}`):
  - fpenv.rs: 11/32 (34%)
  - main.rs: 33/252 (13%)
  - math.rs: 24/94 (26%)
  - weighted overall: 68/378 = 18.0%
  Inspecting the matches: essentially all are either (a) function
  signatures/constant names/algorithm steps the spec normatively pins
  verbatim in its body (§5.1 dot_seq pseudocode, §6.2 exp_pinned/EXP_P
  hex constants, §6.3 sin/cos coefficients, §1.3 FTZ/DAZ asm mnemonics),
  or (b) generic one-line Rust idioms (`let mut acc: f32 = 0.0;`,
  `for i in 0..a.len() {`) that any two independent implementations of
  the same pinned algorithm would produce.
- Identifier-naming check: shared function names across src/verify/verify2
  (dot_seq, sum_seq, matvec, exp_pinned, sin_pinned, cos_pinned,
  ldexp_exact, widen_bf16, rmsnorm, table_digest, pin_ftz_daz, etc.) were
  checked against the spec BODY (not just the informative Appendix A).
  Most are literally named in the normative body text itself (e.g. §5.1
  prose says "`dot_seq` is order-sensitive by design"; §6.2 header says
  "route (b), pinned Cephes-pattern polynomial"; §1.3 says "FTZ/DAZ MUST
  be pinned" — explaining `_pinned`/`pin_` naming without needing to read
  src/). Two exceptions: `pin_ftz_daz` and `widen_bf16` as exact strings
  do not appear anywhere in the spec body OR Appendix A (appendix only
  cites file:line ranges, not identifier names) — appendix A grep count
  for "pin_ftz_daz" = 0 hits. Their appearance in verify2 identical to
  src/verify is plausibly explained by the spec's own vocabulary
  ("pinned", "widening" in §4 title) rather than by reading src/, but
  this is inference, not proof — flagging as the one soft spot in
  independence.
- No evidence of file copy-paste; overlap is at the "same spec, same
  natural implementation" level, not at the "renamed clone" level.

  audit's stated allowance. It does NOT print identifier names beyond
  what's already named in the body (checked: no function name appears
  in Appendix A that isn't already used in the body text).
  This is the mechanism that plausibly explains the CIS2_REF/inv_freq
  digest constants known in advance (they are literally printed in the
  spec body / referenced docs, by design — that's the pre-registration,
  not a leak).
- Appendix B documents known reference inconsistencies/gaps (§14) —
  again informative, doesn't hand over src/ code.
- Nothing found in the body that could only have been known by reading
  src/ line-by-line rather than the spec text.

## Verdict: INDEPENDENT

cis2-verify2 is an independent implementation of CIS2_SPEC_v0.1.md.
Overlap with src/verify is at the level the spec itself mandates
(pinned constants, pinned algorithm steps, and identifier names the
spec's own prose already uses) plus ordinary idiomatic-Rust overlap —
not verbatim code reuse. Git history shows single-commit fresh authorship
with no copy/rename. CI comparison is a real literal digest gate (not
theater), both ISA legs build and run the verify2 crate specifically,
FMA gates are real (grep + objdump) and passed. A fresh workflow_dispatch
re-run reproduces the exact CIS2_REF and inv_freq digests on both
x86_64 and aarch64.

Soft spot (not disqualifying): identifiers `pin_ftz_daz` and `widen_bf16`
match src/verify exactly and are not literally present anywhere in the
spec text (body or appendix) as those exact tokens — plausibly explained
by convergent naming from the spec's own vocabulary ("pinned", "widening"),
but this could not be proven beyond inference. Recommend noting this in
any public claim rather than treating independence as absolute/proven.
