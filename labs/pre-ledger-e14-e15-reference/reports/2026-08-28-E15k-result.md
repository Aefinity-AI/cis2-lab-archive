## Pass 2 (this report): root cause found, resolved

**Root cause**: `docs/CIS2_SPEC_v0.2.md` §12.1's written witness-chain
item order (table_digest, inv_freq_table_digest, weights, tokenizer,
config) never matched the actual reference implementation
(`src/main.rs`: weights, tokenizer, config, table, inv_freq) — the same
binary whose output the section pins as `CIS2_REF=a0c563ef...`. The C
clean-room (`verify3/model.c`, E15j) had correctly transcribed the
spec's (wrong) prose word-for-word. Every one of the five 32-byte
inputs was already proven bit-identical; only their SHA-256-update
*order* differed, which is enough to produce a wholly unrelated final
digest with zero correlation to input similarity.

**Class A (spec defect)**, not class B (verify3 bug) — the C code was
correct relative to the document it was built from; the document was
wrong relative to its own reference implementation.

**Fix applied**: reordered §12.1 items 1-5 in the spec to match
`src/main.rs` (with an inline correction note), and reordered the five
`cis2_sha256_update` calls in `verify3/model.c` to match.
