LIMITS OF THE CHECK. It sees the kernel page cache of the listed files only: not the disk or controller firmware cache, not the drive's own readahead, not a hypervisor or a file system layer (overlay, btrfs, ZFS) below the page cache. A listed directory or other non-regular file (the helper prints N and counts it as nonregular) fails the check, and so does an empty file on a frozen list (the helper prints F 0 0 0 and counts it as empty): the helper itself reads both as 0 pages, so the runner refuses them (a guard added in revision 3); the frozen lists hold neither. The venv walk of P lists regular files only, and empty files that sit in the venv (for example an empty __init__.py) simply count as 0 pages and are tolerated. The runner's own Python imports some modules lazily after the drop, so a little unlisted disk traffic can overlap the first milliseconds of an arm; it is negligible against about 15 s and is part of the limits of cold. The list of P is a RULE, not a frozen list: the regular files found by walking the venv at check time (so the count can differ between hosts and is recorded per host in the rows); the lists of R, C, Rv, Cv and Q are exact templates over the host's paths. The helper exits 0 even when it found errors: its SUM line carries the errors count (a run without a SUM line counts as an error), so nobody reads its return code as the verdict (the runner records the return code and never uses it in a decision). A weights file on tmpfs reads as fully resident (verified on /dev/shm), so the cold control fails and the host ends NOT RUN INVALID. The reason words "cold cache not dropped" also cover the cases in which the drop works but the file cannot be cold: sudo works but the write to /proc/sys/vm/drop_caches fails (a read-only /proc/sys, a restricted sudoers rule), the file is on tmpfs, or another process maps it; the RESULT line then says "cold cache not dropped, or the file cannot be cold (tmpfs, mapped by another process)". An arm that fails the check three times in a row while the cold control passed (for example any one resident page among the roughly 30,000 files of the venv, or a venv file mapped by a stray process) ends that arm alone NOT RUN INVALID; the other arms go on, and a P NOT RUN INVALID does not touch the labelled R and C pair.

THE CHECK MUST BITE (D3). Two untimed controls inside the job, before any timed rep; both readings go into the RESULT line and into every row. (i) WARM control: read the weights file once (to /dev/null), run the helper: resident pages must be at least 90 percent of the file's pages; if it fails, the helper cannot see a warm file and the host ends INVALID ("cold check cannot bite"). (ii) COLD control: drop, run the helper on the weights file: 0 pages; up to three tries; if all three fail the host ends NOT RUN INVALID ("cold cache not dropped"). After the last timed rep the warm control is run once more (the helper still sees a warm file); a failure there ends the host INVALID ("cold check cannot bite"), because the readings of the timed reps cannot then be trusted.
