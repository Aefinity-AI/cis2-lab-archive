QUESTION. On the same small model and the same 64 teacher-forced tokens on an old laptop CPU, is our Rust implementation of CIS-2 (cis2_ref) faster, level or slower than our C implementation (verify3) (implementation against implementation, not language alone), how do a Rust program calling a library kernel, PyTorch and llama.cpp compare (framework), and how much memory does each use?

WHAT IS COMPARED (all on SmolLM2-135M, one weights file per format, sha256 recorded before the initial timing run).
 L-R  Rust-fixed: cis2_ref, fixed-order scalar fp32, no-hash plain-generation mode (small patch if missing; the patch is written before any timing, limited to switching off hashing and receipt output with no change to the decode loop, by one author in one session, and its diff sha256 and line count are recorded and frozen with the other flags; the same is done for L-C, and unequal patch size is stated in the result). NOT PURE RUST: cis2-spec Cargo.toml enables tokenizers with features = ["onig"] and Cargo.lock lists onig and onig_sys (C Oniguruma; read 2026-10-04). Cargo.lock package count recorded (104 today).
 L-C  C-fixed: verify3 / sv5_driver, same algorithm, no-hash plain-generation mode. C11, libc and libm only.

METRIC AND STATISTIC. Timing is the in-process wall of decode steps 2 to 64 (63 steps) per prompt. Per-rep value = (8 x 63 tokens) divided by the sum of the 8 prompt walls, in tokens per second. Statistic = median of 5 per-rep values per arm per host (10 when a label is INCONCLUSIVE, once). Threads N=1 for every label; N=2 on box1 and box2 is reported with no label. Memory: peak PSS and peak anonymous bytes sampled every 50 ms from /proc/<pid>/smaps_rollup over the whole process, plus VmHWM; the values used are the medians of the 5 per-rep peaks of PSS and of anonymous bytes. The Rust safetensors crate maps the weights file (mmap) and the C loader read()s it, so PSS carries an I/O-method effect; the result states the load method of each arm. Reported with no label: prefill tokens per second, load time, time from process start to the opening generated token with warm page cache (cold cache belongs to rust-4).
