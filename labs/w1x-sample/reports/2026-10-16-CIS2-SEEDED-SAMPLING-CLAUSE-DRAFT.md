# CIS-2 seeded sampling clause — DRAFT v0 (2026-10-16, Fable)

Published 2026-10-16 as part of the CIS-2 archive.

Why: state/reports/prior-art/seeded-sampling.md (2026-10-16) finds no public spec that pins a PRNG, its
seeding and the uniform-to-float conversion so that two independent implementations draw the same token
sequence bit-for-bit (Q6 OPEN). vLLM/SGLang/Thinking Machines reach batch invariance and same-hardware
seeded reproducibility; SGLang's stateless hash sampler is the closest design and claims nothing across
hardware. CIS-2 pins every arithmetic step already (§5 sums, §6.2 exp, §6.5 ln, §11.2 first-index argmax),
so a stateless sampler needs only ONE new primitive: a pinned 32-bit hash. Everything else is reuse.

## Proposed text (to become spec §14 "Seeded sampling"; v0.3b stays greedy-only, this is the v0.4 track)

14.0 Scope. When `sample_mode = 1` the decode step picks the next token by Gumbel-max sampling over the
fp32 logits of §11 with a stateless, seed-keyed noise source. `sample_mode = 0` is the greedy decode of
§11.2 and its receipts are byte-identical to v0.3b (this clause adds nothing to a greedy receipt).

14.1 Parameters (all part of the receipt header, §14.5):
- `seed`: u64.
- `temperature`: f32, finite, `> 0`. (`temperature == 0` with `sample_mode = 1` is INVALID; use
  `sample_mode = 0`.)
- `top_k`: u32, `0` = disabled.
- `top_p`: f32 in `(0, 1]`, `1.0` = disabled.

14.2 Noise source (the only new primitive).
- Hash: MurmurHash3_x86_32 (Appleby, public domain; the `MurmurHash3_x86_32` function of the reference
  `MurmurHash3.cpp`), applied to the 16-byte key
  `seed (u64 LE, 8 bytes) || step (u32 LE, 4 bytes) || vocab_index (u32 LE, 4 bytes)` with the hash seed
  parameter `0x43495332` (ASCII "CIS2"). Known-answer vectors in §14.6.
- Uniform: `u = f32((h >> 9) * 2 + 1) * 2^-24`. The integer `(h >> 9) * 2 + 1` is odd and `< 2^24`, so
  `u` is EXACT in f32 and lies in `(2^-24, 1 - 2^-24)`; `ln_pinned(u)` is therefore finite and non-zero.
- Gumbel: `g = 0.0f - ln_pinned(0.0f - ln_pinned(u))` (two §6.5 calls, two exact negations; no FMA, no
  other arithmetic).
The noise for `(seed, step, index)` is a pure function; it does not depend on the batch, the order of
evaluation, the vocabulary size, the hardware or any RNG state. That is the whole point.

14.3 Candidate set (masking), computed on the §11 logits `l[0..V)` (finite by construction):
1. `s_i = l_i / temperature` (f32 division; `temperature == 1.0` leaves every `s_i == l_i` exactly).
2. Rank order: `i` precedes `j` iff `s_i > s_j`, or `s_i == s_j` and `i < j` (descending value, lower
   index first). `rank(i)` = number of indices that precede `i`.
3. top-k: if `top_k > 0`, keep `i` iff `rank(i) < top_k`.
4. top-p: if `top_p < 1.0`, over the kept indices in rank order compute `m = s` of rank 0,
   `e_r = exp_pinned(s_r - m)` (§6.2), `denom = sum_seq(e)` in rank order (§5.3), `p_r = e_r / denom`
   (division, §9.3 style), `c_r = sum_seq(p_0..p_r)` in rank order; keep rank `r` iff `r == 0` or
   `c_{r-1} < top_p`. (The smallest rank prefix whose cumulative probability reaches `top_p`.)
Implementations may use any algorithm that yields the same kept set (sorting is not required).

14.4 Draw. For kept `i`: `z_i = s_i + g_i` (f32 add). For masked `i`: `z_i = -inf`. `next_id` = the
FIRST index attaining the maximum of `z` (the strict-`>` scan of §11.2, applied to `z` instead of `l`).

14.5 Receipt. §12.1 is unchanged for `sample_mode = 0`. For `sample_mode = 1`, immediately after the
prompt token ids (§12.1 item 6) the chain absorbs, in this order: the ASCII bytes `CIS2-SAMPLE-1`
(13 bytes), `seed` (u64 LE), `temperature` (f32 bits, u32 LE), `top_k` (u32 LE), `top_p` (f32 bits,
u32 LE). Item 7 is unchanged: per step the full fp32 logit vector (7a) then `next_id` (7b, now the
SAMPLED id). `argmax_digest` (§12.2) keeps its name and is fed the sampled ids. A greedy verifier
re-running a sampled receipt with `sample_mode = 0` will diverge from step 1 on: that is correct.

14.6 Known-answer vectors (to be generated by the reference and checked by a from-text implementation):
- MurmurHash3_x86_32 KATs: at least the 16-byte key for `(seed=1, step=0, index=0)`, `(1,0,1)`,
  `(1,1,0)`, `(0xffffffffffffffff, 7, 49151)`; plus `u` and `g` bit patterns for each.
- Toy vector: `V = 8`, `l = [1.0, 2.0, 2.0, -1.0, 0.5, 3.0, 3.0, -4.0]`, `seed = 1`, `step = 0`,
  `temperature = 0.8`, `top_k = 4`, `top_p = 0.9` -> kept set, every `z_i` bit pattern, `next_id`.
- Model vector: SmolLM2-135M, prompt "Once upon a time", `seed = 1`, `temperature = 0.8`, `top_k = 40`,
  `top_p = 0.95`, `gen_toks = 16` and `64`: sampled ids + `CIS2_REF`. Informative until two
  independent implementations agree.

## Design notes (not spec text)
- Stateless per-(seed, step, index) noise makes the draw batch-invariant and parallel-safe for free; a
  stateful PRNG (mt19937, Philox stream) would need a pinned consumption order, which is exactly what
  llama.cpp cannot promise across libstdc++/libc++ (prior-art Q3).
- MurmurHash3_x86_32 over Philox4x32-10: 15 lines, no 64-bit multiply, trivially OpenCL/CUDA/Rust/C
  portable, public reference. Philox has official KATs too (Random123) and stays the fallback if a
  reviewer objects to Murmur's non-cryptographic quality (irrelevant here: the seed is not a secret).
- Cost: V hashes + 2V `ln_pinned` per step on top of the forward; negligible next to the LM head matvec.
- What this does NOT claim: statistical quality of the sampler is standard Gumbel-max; the claim is only
  bit-exact reproducibility of the drawn sequence across implementations and hardware.
