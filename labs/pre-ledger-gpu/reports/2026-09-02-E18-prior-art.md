# E18 — Prior art: fp32 (or FP) CPU↔GPU bit-identical transformer/LLM inference from a spec

**Purpose.** Scope any "first" claim for CIS-2-on-GPU (public spec: https://github.com/Aefinity-AI/cis2-spec) against real search results, per the memo critique's items 1 and 5 (`~/projects/claudius-maximus/state/reports/2026-09-02-E18-cis2-gpu-memo.md`). All items below were retrieved via WebSearch/WebFetch on 2026-09-02; no local corpus was assumed.

## Scoped "first" statement (conservative, hostile-reviewer-proof)

If the CIS-2 GPU digest matches the CPU/aarch64 reference digest, the demonstrated result should be scoped as: **the first published instance, to the best of this search, of a full transformer (decoder-only LLM) forward pass producing bit-identical fp32 numerical output between an independently-compiled CPU implementation and an independently-compiled GPU (CUDA) implementation of the same written specification** (no FMA contraction, FTZ/DAZ, pinned left-to-right reduction order, pinned polynomial transcendentals) — as distinct from: (a) integer/fixed-point cross-hardware identity, which is established prior art (CIS-1, this project's own earlier work, and consistent with Gensyn RepOps' likely int8/mixed-precision coverage); (b) bit-exact results obtained via one side *emulating* the other's specific hardware rounding behavior rather than both sides independently conforming to a common spec (arXiv:2606.00279, BF16, GPU-specific SFU-table emulation); (c) same-GPU or same-GPU-architecture reproducibility across batch sizes, tensor-parallel configurations, or repeated runs (Thinking Machines, SGLang, TBIK, EigenAI); (d) reproducible/correctly-rounded BLAS achieving CPU↔GPU identity for linear-algebra primitives or solvers but not demonstrated on a full attention/RoPE/RMSNorm/transcendental transformer stack (ReproBLAS/ExBLAS/OzBLAS); and (e) vendor libraries (cuBLAS, cuDNN, oneMKL), which explicitly disclaim cross-architecture (and a fortiori CPU↔GPU) bitwise guarantees in their own documentation. Framed this narrowly, the claim survives all sixteen items found above; framed any more broadly (e.g. "first bit-identical CPU-GPU ML inference" without the "from a spec, fp32, full transformer" qualifiers) it would be vulnerable to items #2, #3, and #10.

## Five closest works to cite

1. **Bit-Exact AI Inference Verification Without Performance Tradeoffs**, arXiv:2606.00279 — closest CPU↔GPU bit-exactness result overall; must distinguish emulation-of-specific-hardware (theirs, BF16) from independent-spec-conformance (CIS-2's, fp32).
2. **Gensyn RepOps / REE**, github.com/gensyn-ai/repops-demo, docs.gensyn.ai/tech — closest commercial claim explicitly listing CPU *and* GPU as formally supported targets for bitwise-identical ML operators; precision unconfirmed, no full-model artifact found — needs a follow-up check before finalizing the "first" framing.
3. **OzBLAS / Ozaki-scheme reproducible BLAS**, dl.acm.org/doi/fullHtml/10.1145/3432261.3432270 — the only item found with a *published, peer-reviewed* demonstration of CPU↔GPU bit-wise reproducibility (for CG solvers, not transformers); the numerical-methods lineage CIS-2's pinned-order approach belongs to.
4. **RepDL**, arXiv:2510.09180 (Microsoft) — same fp32 CPU-or-GPU goal stated in the abstract, but per our fetch has no experimental cross-device digest table for any model; the nearest "someone else stated this exact goal" citation.
5. **NVIDIA cuBLAS/cuDNN docs** + **PyTorch determinism docs** — not competing claims but essential negative-evidence citations establishing that the standard/vendor path explicitly does not and cannot deliver what CIS-2 attempts, which is what makes hand-written no-FMA kernels against a pinned spec necessary in the first place.

### What this changes

1. **Gensyn's demo repo is a materially stronger prior-art candidate than the first pass credited it with.** It is a publicly runnable, full-transformer (Llama-3.2-1B-Instruct, fp32), CPU↔GPU bitwise-match artifact with a fixed published digest. The earlier report's "no full-model artifact found" line for item #3 is superseded — anyone can `git clone` + `docker run` and reproduce the claimed match themselves (subject to having the hardware and being willing to trust Gensyn's closed-source op library, which they cannot inspect).
2. **It is still structurally different from CIS-2's claim shape in three ways that survive the correction:**
   - **Not peer-reviewed as a CPU↔GPU result.** The peer-reviewed arXiv paper's own reproducibility experiments are GPU-to-GPU only (T4/3090/A100-40/A100-80); the CPU leg exists only in an unreviewed demo repo.
   - **Not two independent implementations of a shared written spec.** RepOps/`gensyn_onnx2torch` is one closed-source, proprietary library that Gensyn alone wrote and controls for both the CPU and CUDA code paths; the CPU and GPU kernels are two different internal code paths of the same vendor's product, not independently-authored implementations converging on a public spec text the way CIS-2's design requires (and the way CIS-1's aarch64/x86 pair already demonstrated). Nothing outside Gensyn can inspect, audit, or reimplement the actual reproducibility mechanism from public source — only the demo harness (`repops-demo.py`) is public; the op kernels ship as a closed Docker image with no PyPI package and no license file of their own.
   - **Mechanism undisclosed for FMA/FTZ-DAZ.** Neither the public paper nor the public repo states whether FMA is disabled or emulated, or whether FTZ/DAZ subnormal handling is pinned — CIS-2 pins both explicitly and this is auditable in its public spec.
3. **RepDL confirms rather than weakens the earlier finding.** Source-level read confirms fp32-only, per-op (no transformer/attention coverage), no cross-device digest example anywhere in the repo, and — notably — RepDL's mechanism is the *opposite* of CIS-2's on FMA: RepDL's CPU kernel explicitly calls `std::fmaf` (uses FMA, deliberately, as part of achieving a single fixed accumulation order), where CIS-2 disables FMA entirely and relies on FTZ/DAZ + pinned left-to-right summation without fused ops. This is a genuine methodological fork worth citing explicitly in any related-work section: two different "fixed order" strategies (FMA-inclusive vs FMA-free) both claiming reproducibility, for different scopes (per-op vs full transformer).
