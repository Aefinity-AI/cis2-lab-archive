## The obvious hostile question, answered directly

"Of course scalar fp32 is deterministic if you ban FMA and pin a reduction order — that's not
research, it's just arithmetic." **Answered in `03_contract.md`, "A hostile question this gate
list must answer,"** and again in the abstract's own framing: the contribution is not that pinning
IEEE-754's degrees of freedom produces determinism (unsurprising), it is (1) that finding the
*complete* list of degrees of freedom that must be pinned took three rounds of adversarial,
independent reimplementation to discover — two of which failed on the first attempt and located
real gaps (missing transcendental coefficients and RoPE construction in the memo-only attempt;
a witness-chain byte-order self-contradiction in the spec text itself, found by the C clean-room)
— and (2) that a written document, not shared code, is what a second and third party in two
languages actually converged on. This is stated up front rather than left for a reader to infer.

## What remains open (not fixed in this pass — flagged for Justin/Fable, not silently dropped)

1. **H1's exact digest values are not quoted in this paper.** `2026-08-28-H1-result.md` itself does
   not print the literal hex digests for the Qwen2.5-1.5B/512-token legs, only pass/fail verdicts
   per CI job; `09_reproducibility.md` says this explicitly rather than inventing plausible-looking
   hex to fill the gap. A follow-up pass should pull the literal digests from CI run `33214545380`'s
   artifacts and add them to `04_evidence.md`/`09_reproducibility.md` before this is camera-ready,
   since a hostile reviewer will ask "show me the number" for every named CI run.
2. **No PDF was generated.** Neither `pandoc` nor `tectonic`/`xelatex`/`pdflatex` is installed on
   this machine, and per task instructions no system package install was attempted. Only
   `docs/paper/paper.md` (concatenated Markdown, matching the CIS-1 paper's own `paper.md`
   structure) exists; a PDF build step should be run wherever a LaTeX/pandoc toolchain is available
   before arXiv submission (arXiv also accepts a Markdown-to-LaTeX or direct LaTeX source, so this
   is a submission-format task, not a content gap).
3. **Independence audit exists only for the Rust clean-room (`verify2`), not the C one
   (`verify3`).** `E15g-audit`'s style of check (verbatim-line-overlap analysis, git-history
   authorship check) has not been run against `verify3/`. Given `verify3` is written in a different
   language from the reference, code-similarity-based independence auditing is less load-bearing
   there than for `verify2` (a Rust-vs-Rust comparison), but a hostile reviewer could still ask for
   it; not done in this pass.
4. **Table 3-style generated provenance table (`gen_table3.py` in the CIS-1 paper) has no CIS-2
   analogue.** This paper's evidence table (`04_evidence.md`) is hand-maintained, not
   script-generated from a ledger, unlike CIS-1's `gen_table3.py`/`table3_provenance.md`. This is a
   process gap, not a content error, but means a future edit to any digest value has no automated
   check that the paper text stays in sync with the source-of-truth report.
5. **Word count.** Assembled `paper.md` is approximately 12,000 words (`wc -w`), before any PDF
   formatting; no length constraint was given in the task, but arXiv/venue length norms should be
   checked before submission.
