## What this closes

- cis3-0m showed 31/31 layer digests, argmax and tokens already matched; the witness
  differed only because `weights_sha256` binds the merged FILE bytes (cis2-fp
  `src/main.rs:1084-1091`) and the cis3-0m merge produced a different byte layout.
- cis3-0n merges byte-identically, so the witness now matches too. The old Kaggle-pinned
  7B digest 1501ed47… (LLM-5B/5c/cis3-0k) was the output of the mis-merged checkpoint
  (cis3-0m mergebug note) and should not be used as an EXPECTED value.
- Re-pin proposal (not applied here; EXPECTED edits are a separate decision): 7B
  EXPECTED witness = a4a6770e…, bound to merge recipe cis2-fp @ c0a2c34 and this kernel.
